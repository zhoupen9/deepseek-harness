# Agent Note: 在 Host 启动前展示 Desktop 加载窗口

Status: implemented

[English](2026-10-28-desktop-presents-loading-window-before-host.md) | 中文

## 问题

壳会以隐藏状态创建主窗口，并仅在 `enterWorkspace` 中首次显示它；该路径要等 profile 准备、登录 shell 读取、完整 Host Web profile 以及欢迎流程的凭证与语言读取全部完成。因此启动后托盘图标立即出现，但整个 Host 启动期间没有窗口，尽管共享加载页早已载入隐藏窗口。用户无法区分正常启动与卡死，此期间的托盘激活、再次启动和 `dsh://open` 也都看不到可见反应。

## 决策

`reconcileBackend` 在初始 `dsh-app://app/` 文档加载完成后、启动 Host 之前立即展示主窗口。共享加载页在 profile 准备、登录 shell 环境读取、Host 启动和客户端插件加载期间均可见。这恢复了[已归档的立即显示窗口决策](../../archived/architecture/2026-09-09-desktop-immediate-window-and-direct-start.md)中的显示时机。

`bootPagePresented` 记录引导页是当前界面，因此通过托盘、再次启动或 `dsh://open` 的激活会聚焦已展示的窗口，而不是被忽略。欢迎窗口或工作区替换该页面时会清除此标记。`openInitialWindow` 仍只在 Host 就绪并读取凭证和语言后选择界面：欢迎窗口打开并隐藏主窗口，工作区路径则显示已经在展示加载页的同一文档。

初始文档加载失败时不展示窗口，原生恢复对话框仍是唯一可见界面。后续启动失败时，已展示的加载页保留在该对话框之后。[欢迎窗口决策](2026-09-08-desktop-welcome-window-material.zh.md)提供此展示所包裹的引导流程。

## 考虑过的替代方案

**在 Host 就绪前保持窗口隐藏。** 加载页仍会载入并绘制，但用户在数秒的 Host 启动期间只能看到托盘图标，该期间的激活也无反应。展示已载入的页面不增加启动工作。

**以显示状态创建窗口（`show: true`）。** 这会在打包文档完成绘制前显示一个空窗口。在初始加载完成后展示则直接显示引导页，不出现空白帧。

**在展示前等待欢迎流程的决策。** 该决策需要 Host 凭证和语言，因此会继承它本要隐藏的全部延迟。

**用本地完成标记决定引导流程。** [欢迎窗口决策](2026-09-08-desktop-welcome-window-material.zh.md)记录了为何完成标记不能替代冷启动凭证检查；本地标记还会与退登或其他客户端改变后的账号状态不一致。

## 后果

加载页在完整 Host 启动期间可见，托盘、Dock、再次启动和 `dsh://open` 都能聚焦它。窗口控件从首个已加载帧起即可用。启动失败时，原生恢复对话框显示在加载页之上。

首次运行的引导流程会先短暂显示引导页，随后被欢迎窗口替换。用户在启动期间隐藏的窗口会在工作区打开时再次显示。Desktop 启动测试覆盖先展示后启动 Host 以及欢迎窗口替换已展示页面的顺序。
